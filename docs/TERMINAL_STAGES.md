# 퇴근.exe

기본 게임은 사무실을 탐색하며 여섯 가지 업무를 처리하는 코미디 스테이지 게임이다. 메인 → 짧은 소개 → 3인칭 이동 → 장비·NPC 상호작용 → 성공/실패 → 다음 업무/재도전 순서다. WASD·마우스·F·Space와 모바일 이동·시점·상호작용·점프를 지원한다.

| 스테이지 | 문제 | 익히는 것 | 오입력 |
|---|---|---|---|
| 1 | PC 상태 확인 | help, status | 오류 출력 후 재입력 |
| 2 | 마지막 출력 서류 찾기 | ls, cat, 출력 시각 | 오류 출력 후 재입력 |
| 3 | 야근 신청서 무한 출력 | 프로세스와 출력 이력 대조 | PC 폭발 |
| 4 | 사무실 난방이 오븐 온도 | 장치 구역과 설정표 대조 | PC 폭발 |
| 5 | 보안팀장 퇴근 결재 | NPC의 세 요청을 읽고 대화 선택 | 잘못된 선택으로 실패 |
| 6 | 옥상의 마지막 PC 끄기 | 발판 점프와 물리 전원 스위치 | 추락 시 실패 |

명령은 고정된 게임 데이터에만 적용한다. `help`, `ls`, `cat`, `ps` 등 조회는 정상 문법과 대상이면 안전하며, 3단계부터 알 수 없는 명령·파일·잘못된 조치 대상은 폭발한다. help에는 문법을 표시하고 조치의 정답 인수는 표시하지 않는다. 원문에 풀이를 덧붙이지 않는다.

폭발 시 실제 주변 모니터·컴퓨터 메시를 숨기고 같은 메시의 복제물을 회전·분리·낙하시키며, 재도전 때 복구한다. 파편·섬광·카메라 흔들림·SFX도 함께 사용한다. 실패 규칙은 게임 소개·도움말에서 미리 설명하지 않는다. 실패한 PC만 한 버튼으로 재부팅하며 앞선 스테이지의 클리어·해금은 유지한다. 해금된 업무는 선택 화면에서 다시 플레이할 수 있다. 아직 입장하지 않은 이름은 ???로 가리며, 입장 기록은 선택 필드 entered에 저장한다. 기존 8필드 저장도 계속 읽는다. 진행·폭발 횟수는 기존 저장 봉투에 검증 가능한 `stage` 필드로 저장한다. 기존 조사 저장은 새 게임 선택 전 덮어쓰지 않고 보관한다.

기존 사무실·장비 배치, Windows 데이터 경로, Android 패키지·서명, 설정·동의 기반 업데이트는 유지한다. 이전 조사 모드는 `--legacy-investigation`과 기존 회귀 검사로 유지한다.

구현: `stages.json`(문제·원문), `stages_engine.gd`(판정·해금·재도전), `stages_ui.gd`(터미널·폭발·결과), `stages_entry.gd`(메뉴·소개), `stage_world.gd`(주인공·옥상 발판·실제 모델 파손). 실제 기본 실행과 EXE/APK 검사는 `stages_smoke.gd`를 사용한다.
