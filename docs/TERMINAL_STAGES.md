# 퇴근.exe

기본 게임은 터미널 명령으로 회사 PC 여섯 대를 처리하는 코미디 스테이지 게임이다. 메인 화면 → 짧은 소개 한 장 → PC 문제 → 성공/폭발 → 다음 PC/즉시 재도전 순서로 진행한다. 날짜 전환·NPC 인계·보고서는 필수 진행에서 제거한다.

| 스테이지 | 문제 | 익히는 것 | 오입력 |
|---|---|---|---|
| 1 | PC 상태 확인 | help, status | 오류 출력 후 재입력 |
| 2 | 마지막 출력 서류 찾기 | ls, cat, 출력 시각 | 오류 출력 후 재입력 |
| 3 | 야근 신청서 무한 출력 | 프로세스와 출력 이력 대조 | PC 폭발 |
| 4 | 사무실 난방이 오븐 온도 | 장치 구역과 설정표 대조 | PC 폭발 |
| 5 | ‘진짜 최종’ 급여 파일 보관 | 승인 해시와 파일 목록 대조 | PC 폭발 |
| 6 | 퇴근 게이트 열기 | 요청 ID와 최종 회신 대조 | PC 폭발 |

명령은 고정된 게임 데이터에만 적용한다. `help`, `ls`, `cat`, `ps` 등 조회는 정상 문법과 대상이면 안전하며, 3단계부터 알 수 없는 명령·파일·잘못된 조치 대상은 폭발한다. help에는 문법을 표시하고 조치의 정답 인수는 표시하지 않는다. 원문에 풀이를 덧붙이지 않는다.

폭발은 파편·화면 섬광·짧은 카메라 흔들림·SFX로 표현한다. 실패한 PC만 한 버튼으로 재부팅하며 앞선 스테이지의 클리어·해금은 유지한다. 해금된 PC는 선택 화면에서 다시 플레이할 수 있다. 진행·폭발 횟수는 기존 저장 봉투에 검증 가능한 `stage` 필드로 저장한다. 기존 조사 저장은 새 게임 선택 전 덮어쓰지 않고 보관한다.

기존 사무실·장비 배치, Windows 데이터 경로, Android 패키지·서명, 설정·동의 기반 업데이트는 유지한다. 이전 조사 모드는 `--legacy-investigation`과 기존 회귀 검사로 유지한다.

구현: `stages.json`(문제·원문), `stages_engine.gd`(판정·해금·재도전), `stages_ui.gd`(터미널·폭발·결과), `stages_entry.gd`(메뉴·소개). 실제 기본 실행과 EXE/APK 검사는 `stages_smoke.gd`를 사용한다.
