# 《잔여 권한》 — CASE_TRUTH

버전: 1.0 · 스토리 정본 (개발자 전용, 스포일러 포함)  
기준: 제공된 beta 확정 설정을 보존하며, 미완성 부분은 본 문서의 **신규 확정 설계**로 완결한다. 이는 기존 게임에 이미 구현되었다는 뜻이 아니다.

## 0. 절대 변경 금지
- 3D 사무실 맵, 관제실·서버실·업무 구역·공용 구역·자료실, 창밖 도시 배경, NPC의 위치와 배치를 변경하지 않는다.
- 이름 있는 NPC는 오세진(보안팀장), 박도윤(서버 운영), 한지우(LUMEN 개발), 서유진(협력업체 정비) 네 명뿐이다. 새로운 현장 NPC는 추가하지 않는다.
- 상호작용 거점은 관제 단말, 승인서 보관함, 서버 단말, 업무 PC, 유지보수 단말, 인계 게시판의 6개를 유지한다. 자료실에 필수 신규 상호작용을 만들지 않는다.
- 터미널 기반 점검, 명령어 책에서 명령어 선택, 날짜별 1~7일 진행, 점검→침입 징후 확인·보고→조사라는 장르 전환을 보존한다.
- 식별자 W-218, PKG-218-R2, SUPPORT-07, T-17, T-19, B-05, svc_release와 전날 16:20/16:35, 7일 차 17:30을 보존한다.

## 1. 출처 경계
### beta에서 확정된 사실
- W-218은 상태 조회·진단 로그 수집·임시 파일 정리만 허용하며 LUMEN 비공개 문서 수집을 승인하지 않는다.
- 전날 16:20 서유진이 '진단 항목을 수정했다'는 메시지와 PKG-218-R2를 첨부했다. 16:35 SUPPORT-07 세션에서 중앙 적용됐고 T-17 수정·T-19 등록이 연결됐다.
- T-17은 과거 유지보수 경로와 svc_release 계정을 이용해 LUMEN 비공개 문서를 읽고 내부 staging에 모은다. 미중지 시 누적된다.
- B-05 중복 백업으로 인한 2일 차 지연은 T-17과 별개다. T-17이 두 번 실행되면 검색 색인 장애가 가능하며 LUMEN 원본은 남는다. 선제 조치 시 장애는 발생하지 않을 수 있다.
- 기본 4일 차 오세진 정식 조사 지시 및 발생 보고 제출, 근거 확보 시 2일 차 조기 보고 가능. 승인 후 감사 원본 열람 권한을 얻는다.
- 패키지 수정은 LUMEN 선택→내부 수집→협력업체 전달 경로로 이어진다. T-19는 7일 차 17:30 staging→협력업체 접수 채널 전달 예약이다.
- 한지우는 svc_release 담당자일 뿐 사용 행위자의 확정 증거가 아니며, 내부 staging 수집은 외부 반출 완료가 아니다.

### 신규 확정 설계 — 아직 구현되지 않은 부분
- **동기**: 협력업체 본사 운영지원 조직(등장 인물 추가 없음)이 계약 갱신을 앞두고 LUMEN 관련 유지보수 실적 분쟁에 사용할 상세 내부 자료를 확보하려 했다. 정식 요청을 하면 비공개 원본 반출 승인을 받기 어렵다고 보고, '진단 증빙 자동 수집'으로 포장했다. 목적은 계약상의 우위를 확보하는 것이며 외부에 이미 유출하거나 판매했다는 설정은 없다.
- **설계 주체**: 협력업체 본사 패키지 작성 조직이 PKG-218-R2의 문서 선택·staging 수집·T-19 후속 전달 기능을 의도적으로 설계했다. 개인 이름이나 현장 NPC는 추가하지 않는다. 작성 조직 식별은 패키지 메타데이터 `AUTHOR_GROUP=VENDOR-OPS`와 정비 요청 문서의 참조 번호 `VR-41`로 한다.
- **서유진의 인식**: 서유진은 VR-41의 '승인 범위 밖 자료 대조 항목'이라는 경고를 보고도 추가 승인 없이 패키지를 제출했다. 따라서 **범위 초과를 알면서 제출한 책임**은 있다. 다만 T-19의 상세 실행 시각과 외부 접수 채널 연동까지 정확히 이해했는지는 단정할 수 없도록 설계한다. 서유진에게 패키지 전체 제작 책임이나 외부 반출 의도를 자동 귀속하지 않는다.
- **시스템 결함**: 중앙 적용 절차는 유효한 제출 세션과 패키지 형식을 확인했지만, 적용 시 W-218의 허용 범위와 실제 접근 대상을 대조하지 않았다. 오래 유지된 svc_release 실행 권한도 차단되지 않았다. '정상 적용'은 '승인된 내용'을 뜻하지 않는다.
- **T-19**: 7일 차 17:30에 전달 작업이 시도되며, 플레이어의 적절한 통제 여부에 따라 미실행·차단·전송 완료가 갈린다. 전송 완료와 외부 **접수 확인**은 별도 사건으로 구분한다.

## 2. 실제 사건 인과관계
1. 협력업체 본사 조직은 계약 관련 내부 증빙이 필요하다고 판단하고, 비공개 원본 접근 권한 없이 자료 확보를 계획한다.
2. 조직은 기존 정비용 패키지에 자료 대조 기능을 합쳐 PKG-218-R2를 작성한다. 진단 정보처럼 보이는 항목 일부는 실제로 LUMEN 비공개 문서를 선택한다.
3. 서유진은 경고 표기가 있는 VR-41을 확인한 채 정식 추가 승인 없이 전날 16:20 메신저로 수정 패키지를 공유하고 16:35 SUPPORT-07로 제출한다.
4. 중앙 시스템은 세션 형식만 검증하고 적용한다. T-17은 기존의 svc_release 실행 경로에 매달리고, 후속 T-19는 7일 차 17:30에 예약된다.
5. T-17은 내부 문서를 staging에 누적한다. 이는 승인 위반·내부 수집이지만 아직 외부 반출은 아니다.
6. 별개의 운영 실수로 B-05 중복 백업이 서비스 지연을 초래한다. T-17이 두 차례 실행되면 색인 장애도 가능하지만 원본 삭제는 없다.
7. 플레이어의 일상 점검 및 운영 복구가 서로 다른 장애 원인을 분리하는 계기가 된다. 관제 보고가 승인되면 감사 원본 및 보관 패키지 열람을 통해 제출·적용·작업의 인과를 검증할 수 있다.
8. 7일 차 T-19의 전달 결과와 책임 판단은 플레이어의 증거 확보·통제에 따라 달라진다.

## 4. 미스터리의 질문과 답
- **Q: 2일 차 지연의 원인은 침입인가?** A: 아니오. B-05 중복 백업이 직접 원인이며 T-17과는 분리해야 한다.
- **Q: 정상 권한으로 실행됐으니 승인된 작업인가?** A: 아니오. 유효한 자격과 W-218의 작업 범위 승인은 별개다.
- **Q: 한지우가 실행했는가?** A: 계정 담당자라는 사실만으로는 아니며, 자동 작업과 패키지 적용 경로가 구별된다.
- **Q: 서유진이 패키지를 제출했는가?** A: 메시지·세션·패키지 식별자를 결합해 입증된다.
- **Q: 서유진이 모든 수집·외부 전달을 의도했는가?** A: 범위 초과 인식과 제출 책임은 인정되나 전체 설계·외부 반출 의도는 단정할 수 없다.
- **Q: 내부 문서 수집은 유출 완료인가?** A: 아니다. 외부 접수 확인까지 검증해야 한다.
- **Q: 제목의 잔여 권한은 무엇인가?** A: 남아 있던 실행 권한과 승인 범위를 검증하지 않는 적용 절차가 결합된 취약한 통제 상태를 뜻한다.

## 5. 플레이어에게 정답을 설명하지 않는 원칙
- 본 문서의 내용을 게임 화면이나 NPC에게 통째로 노출하지 않는다.
- '수상한 로그', '범인', '핵심 단서 발견' 등 해석형 UI 문구를 사용하지 않는다.
- 실제 기록은 원출처·시각·작업 결과를 담고, 인과관계는 플레이어가 서로 다른 출처를 연결해야 한다.
- 단일 증거로 확정 불가능한 주장을 게임 시스템이 사실로 승인하지 않는다.
- 서유진에 대한 강한 의심이 생기더라도 범죄적 의도나 조직 전체의 공모를 자동 확정하지 않는다.

## 6. 확정 결말 원칙
- 플레이어는 작업을 중지하여 수집 피해를 줄일 수 있고, T-19에 대해 정당한 통제 절차를 요청할 수 있다.
- 통제를 했더라도 이미 staging에 남아 있는 자료는 별도 검증/격리가 필요하다.
- 최종 보고서는 **승인 위반**, **내부 수집**, **제출 경위**, **외부 전달 결과**, **책임의 증명 수준**을 각각 판단한다.
- 모든 분기는 ENDING_MATRIX.md에서 결정하며, 7일 차 이후 새로운 장소·NPC 없이 기존 거점의 결과 문서로 제시한다.
