# 《잔여 권한》 — EVIDENCE_GRAPH

버전: 1.0 · 증거/추론 정본 · 개발자 전용  
대응: CASE_TRUTH 1.0, DAILY_STORY 1.0, ENDING_MATRIX 1.0

## 0. 설계 원칙
**단서는 '주워야 하는 반짝이는 물건'이 아니라, 업무 기록으로 자연스럽게 발생한 사실이다.** 터미널은 로그를 보여줄 뿐 중요성을 설명하지 않는다. 명령어 책은 '어떻게 조회하는가'만 도와주고 '어떤 기록이 범인의 증거인가'를 안내하지 않는다.

## 2. 추론 그래프 — 원본에서 주장까지
- `C01: 승인 범위 초과` ← E01 + E03. E02만으로 범위 초과를 입증할 수 없다.
- `C02: 실제 내부 수집` ← E03 + E04. 접근 로그만으로 수집 완료라 단정하지 않는다.
- `C03: B-05가 서비스 지연 원인` ← E05 + 운영 지연 시각. C01과 독립.
- `C04: 반복 T-17과 색인 장애의 연관` ← E07 + E06(색인 상태); T-17 미재실행 분기에서는 C04를 강제하지 않는다.
- `C05: 서유진이 수정 패키지를 제출` ← E08 + E09 + 동일 PKG-218-R2 식별자.
- `C06: 그 제출이 T-17 수정·T-19 등록을 일으킴` ← E09 + E10 + E11.
- `C07: 패키지 작성과 제출은 다른 역할` ← E13 + E08 + E09.
- `C08: 서유진이 범위 초과 가능성을 인식한 채 제출` ← E12 수신/경고 + E08 제출 + E01 승인서; '외부 반출 의도'와 다르다.
- `C09: 조직의 내부 자료 확보 목적` ← E14 + E11 + E13. 특정 개인의 범죄 의도까지 자동 확정하지 않는다.
- `C10: 외부 전달 예약` ← E10 + E15. 예약 자체는 발송 증거가 아니다.
- `C11: 전달 통제 성공` ← E16 + E17의 미실행/차단 상태.
- `C12: 외부 접수 확인` ← E17 발송 성공 + E18 접수 확인. E18 부재라면 '수신 불명'만 가능.

## 4. 화면 및 서사 노출 규칙
- 로그 행은 동일한 서체·크기·색으로 출력한다. 실제 시스템 에러는 상태 코드로 표시할 수 있으나 '중요 단서' 스타일을 쓰지 않는다.
- 시스템에서 '자료 수집'을 숨기기 위해 기록을 조작하지 않는다. 정확한 로그를 열람하는 방법 자체가 플레이어의 행동이어야 한다.
- `E12`, `E14`는 문서 제목이 아니라 정상 업무 카테고리(정비 요청 이력·계약 지원 기록) 속에서 조회한다.
- 수집 기록 저장 UI는 `북마크` 또는 `보고서 첨부`로 표시하며, '핵심 단서 3/5' 같은 정답 카운터는 사용하지 않는다.
- 플레이어가 서로 다른 증거를 연결할 때만 주장 입력란을 열고, 즉각적인 '정답' 이펙트보다 추가 열람 권한/질문/대조 결과를 제공한다.
- 명령어 책에서는 예를 들어 '작업 이력 보기', '접근 기록 보기' 같은 **기능명**만 안내한다. '범인이 남긴 T-17 찾기' 같은 지시는 금지.
- NPC는 본인이 실제로 아는 사실만 대답한다. 인물의 추정은 진술임을 구분한다.

## 5. 추론 난이도 설계
- **초급(D1~D2)**: 무엇이 정상 운용인지 학습, B-05 중복 여부 식별. 확인 원본 1~2개.
- **중급(D2~D4)**: W-218과 실제 접근/수집의 불일치를 2~3개 자료로 입증. 조기 보고 선택 가능.
- **중상급(D5~D6)**: 작성 조직·제출자·실행 계정 담당자를 분리하고 역할별 책임을 구분. 서로 다른 출처 3개 이상.
- **최종(D7)**: 예약/실행/접수 단계와 사람의 의도/행위를 구분해 보고. 증거가 미흡하면 '불명'도 적법한 결론.

## 6. 실패 방지/재방문
- 놓친 E01~E15는 날짜가 지나도 기존 거점에서 재열람 가능(원본 삭제 이벤트 없음).
- 조기 T-17 중지 시 E03~04의 **과거 실행 기록**은 유지한다. 예방 선택이 추리 불능으로 이어지지 않아야 한다.
- D4 보고 보완은 같은 날 재제출 가능. 입증 전 E09~E11 잠금을 우회시키는 '친절한 자동 공개'는 금지.
- T-19 통제 실패와 조사 실패는 다른 결과 축이다. 플레이어의 성급한 보고는 기록에 남지만 스토리가 즉시 종료되지는 않는다.

## 7. 구현 검수 시나리오
1. E08만 열면 제출 사실을 확인할 수 있지만 T-19 의도는 알 수 없어야 한다.
2. E02만 열면 한지우를 범인으로 판정할 수 없어야 한다.
3. E03+E04+E01로 승인 위반 보고가 가능해야 한다.
4. E05와 E07이 동시에 존재해도 B-05와 T-17의 장애 원인은 합쳐지면 안 된다.
5. 조기 보고/조기 중지 시에도 D5~D7의 조사 핵심 경로가 유지돼야 한다.
6. E17 전송 성공만 있으면 E18 없는 상태에서 '외부 접수 완료' 선택이 근거 부족으로 처리돼야 한다.
7. 스토리 정답을 모르는 테스트 플레이어가 터미널 출력의 강조 표시만 보고 핵심 사건을 알아낼 수 없어야 한다.
