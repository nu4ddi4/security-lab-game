# 사건 정본 구현

첨부받은 CASE_TRUTH / DAILY_STORY / EVIDENCE_GRAPH / ENDING_MATRIX 1.0을 기준으로 한다. 이 디렉터리는 개발자용이며 게임 빌드에 포함하지 않는다.

- 기존 사무실, NPC 네 명과 위치, 상호작용 거점 여섯 개를 유지한다.
- 기록은 업무 시스템의 원문으로 작성한다. 의미를 설명하는 경고·정답 안내·단서별 색상은 사용하지 않는다. HUD는 당일 업무만 표시하며 증거 확보에 따라 다음 기록이나 인물을 지목하지 않는다.
- 플레이어가 원문을 선택해 대조 기록을 접수한다. 인과 연결은 독립된 원문의 종류·대상·식별자를 검증한다. 자동 발견이나 단서 완료 수를 표시하지 않는다.
- 저장 호환성을 위해 기존 `records.*.evidence` 값은 유지한다. 정본 E01~E19는 별도 `graphId`와 원문 template으로 대응하며 화면에는 식별 점수를 표시하지 않는다.
- 업무 시각은 실제 PC 시계에 의존하지 않는다. 7일차 정시 확인에서 09:00 → 17:30(실행 중) → 17:31(처리 완료) → 17:35(채널 회신)로 진행한다. 실행 전 보류/대상 없음/격리 시 17:30에 미실행으로 기록한다. 업무 확인은 플레이어가 진행하며 예약 날짜·시각은 조기 보고에도 바뀌지 않는다.
- 통제 요청에는 보고 승인과 적용·예약 원문이 필요하다. 승인은 실행과 분리한다. 실행 중 차단과 발송 완료 후 조치를 구분하고, 이미 발송한 결과는 바꾸지 않는다. staging 격리는 7일차 별도 조치이며 과거 자료 목록을 삭제하지 않는다.
- 최종 보고는 원문 대조 이후 항목별로 작성하며 자동 선택하지 않는다. 판단 보류를 허용한다. 접수 당시의 인용·연결을 보존하고, 이후 시각/통제 상태 변경 시 재접수한다.
- ENDING_MATRIX의 중첩 규칙에 따라 과잉 주장 또는 핵심 근거 미비를 F로 먼저 평가한다. 나머지는 접수 상태와 논증 수준에 따라 A~E로 나눈다. 물리적인 전송/접수 상태는 보고 평가와 별도로 저장한다.
- 종결 문서에는 플레이어가 조회한 운영 원문과 접수한 보고만 수록한다. 결과 원문 미열람 시 결말 제목을 통해 미확인 접수 사실을 노출하지 않는다. 이후 기존 단말에서 해당 원문을 조회할 수 있으나 종결한 보고를 자동 수정하지 않는다.
- 기존 schema/contract/contentVersion 및 저장 경로를 유지한다. `casework`가 없는 저장은 이전 원문 정의로 먼저 검증한 뒤 진행·메모·열람·보고를 유지해 새 규칙으로 옮긴다. 이전 7일차 프로토타입 종료 저장은 7일차 정시 확인 전으로 이어진다. 손상된 저장을 초기화하지 않는다.

규칙 검사는 여섯 결말, 조기 보고·중지, 실행 중/완료 후 통제, 무응답, 격리/대상 없음, 근거 위조, 실제 이전 저장의 이행을 다룬다. 장면 검사는 원문 선택 → 대조 → 통제 요청/실행 → 정시 확인 → 최종 보고 → 종결 문서와 화면 비율을 검증한다.
