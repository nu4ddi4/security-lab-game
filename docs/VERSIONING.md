# 버전 관리

`main`은 정식 릴리스, `beta`는 **다음 정식 릴리스 목표**를 개발한다. 현재 소스 목표는 `0.8.0`이며 빌드 표기는 `0.8.0-beta.1`이다.

| 상황 | 예시 |
| --- | --- |
| 같은 목표 버전의 테스트 배포 | `0.8.0-beta.1` → `0.8.0-beta.2` → `0.8.0-beta.3` |
| 검증 후 main 승격·정식 배포 | `0.8.0` |
| 정식 버전의 버그 수정 | `0.8.1-beta.1` → `0.8.1` |
| 다음 기능 업데이트 | `0.9.0-beta.1` → `0.9.0` |

매 커밋마다 버전을 올리지 않는다. **테스트 배포할 때만 베타 순번을 올리고**, 목표가 달라질 때 다음 정식 버전을 정한다. 호환성을 깨는 변경은 major를 올린다. 커밋·푸시와 릴리스는 별개이며, 이미 공유한 태그·배포 파일은 덮어쓰지 않는다.

현재 버전 설정은 `godot/project.godot`, `godot/prototype/version.json`/`build_info.json`에 있다. Godot 베타의 기본 버전은 `0.8.0`, 런타임 빌드 메타데이터는 `0.8.0-beta.1`을 사용한다.

현재 배포 스크립트는 `beta.1`이 고정되어 있고 태그·파일명·Android versionCode에 베타 순번을 반영하지 않는다. **beta.2 재배포 전에는** 빌드·업데이트 비교·태그/파일명·Android versionCode의 순번 처리를 함께 보완한다. 같은 태그에 새 바이너리를 덮어 올리지 않는다.

이번 기존 릴리스는 표시 이름만 `SecurityLab-0.8.0-beta.1`로 맞춘다. 태그·파일·내부 버전·체크섬·업데이트 manifest는 검증된 0.4.0 그대로 유지하며, 0.8.0 바이너리를 새로 배포한 것은 아니다.
