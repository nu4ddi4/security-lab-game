# 베타 상호작용·모바일 개선

## 반영한 동작

- 장비·NPC·문은 **F / 상호작용 버튼**으로 조작한다. E와 별도 살펴보기 버튼은 사용하지 않는다. 장비를 여는 것만으로 원본·증거를 획득하지 않는다.
- 상호작용 거리는 2.65m에서 **3.4m**로 조정했다. 중심 조준선 우선, 가장자리에는 반경 **0.16m**의 여유를 적용한다. 후보마다 가시선을 검사하며 벽·문을 통과해 선택하지 않는다. 장비 충돌 영역을 크게 겹치게 만드는 방식은 사용하지 않았다.
- 마우스를 캡처한 상태에서는 중앙 조준점을, 자유 포인터 상태에서는 실제 포인터 위치를 사용한다. 모바일에서는 장비를 탭해 선택하고 상호작용 버튼을 눌러 연다. 탭만으로 단말이나 대화를 열지 않는다.
- 화면의 짧은 변을 기준으로 UI 좌표계를 맞추고 비율을 확장한다. Android는 센서 방향을 사용하며 가로·세로 전환을 지원한다. 작은 화면에서는 메신저 연락처를 선택 상자로 바꾸고 단말을 한 열로 표시한다. 안전 영역과 화면 키보드 높이를 반영한다.
- 터치는 왼쪽 엄지의 이동 스틱, 오른쪽 시점 쓸기, 단일 상호작용 버튼으로 구성한다. 이동에는 작은 데드존을 적용하고, 시점 감도는 화면 너비에 비례한다. 이동과 시점 손가락을 따로 추적한다. 단말·대화 내용은 손가락으로 스크롤하며 UI를 열거나 앱이 포커스를 잃으면 조작 상태를 해제한다. 키보드도 함께 사용할 수 있다.
- 장비를 처음 열 때 명령 목록을 출력하지 않는다. `help` 입력 후 현재 장비의 명령을 보여 준다. 자동완성 목록도 도움말을 요청한 후 사용한다. 작은 화면에서는 별도 명령 사이드바 대신 단말 출력으로 도움말을 읽는다.
- **4일차 보안팀장 메시지의 직접 조사 지시**를 업무 전환 시점으로 사용한다. 이전에는 발생 보고 탭, 수집·승인 상태, 조사 질문·명령·파일 안내를 숨긴다. 기존 저장에서 이미 보고를 승인받았다면 조사 권한을 유지한다. 저장 스키마는 변경하지 않았다.
- 현재 목표에 공중의 밝은 화살표와 바닥 링을 표시한다. 인계·운영 복구·조사 단계에 따라 대상이 바뀌고 완료한 목표 표시는 사라진다.
- 대화 종료 시 현재 카메라 각도를 유지한다. 플레이어 몸체 방향을 시선에 맞추므로 다음 이동·시점 입력에서도 갑자기 돌아가지 않는다. 시야각만 짧게 부드럽게 복원한다.

## 로딩 원인과 반영한 최적화

기존 시작 경로는 사무실 자원을 동기적으로 읽고, 사무실과 외부 도시를 생성한 뒤 UI를 만들었다. 이 동안 첫 화면을 그릴 수 없었다. 베타 스테이징은 모델·텍스처 가져오기 정책을 복사하지 않아 기존 포트에서 설정한 GPU 텍스처 압축도 사라졌다. 무손실 텍스처를 읽고 해제한 뒤 GPU로 전송하는 비용과 최초 셰이더 준비가 모바일에서 특히 불리한 구조였다.

지금은 먼저 로딩 화면을 한 프레임 그린 뒤 모델을 스레드에서 읽는다. 자료 준비 → 모델 로딩 → 장비 배치 → 화면 준비 순으로 진행 상태를 보여 준다. 모델 생성과 물리 장면 구성은 주 스레드에 남아 있다. 이미 읽은 `PackedScene`을 월드에 전달해 다시 읽지 않는다. 베타 Windows·Android 스테이징은 기존 모델의 `.import` 정책을 가져간다. 첫 가져오기에서 GLB의 이미지 파일이 생성된 다음, 기존 Native 빌드와 같은 GPU 압축 모드를 설정하고 해당 텍스처를 다시 가져온다. 이미지 생성 전에 `.import`만 복사하면 새 빌드에서 파일을 찾지 못하므로 순서를 지킨다. 모바일의 3D 해상도 65%, MSAA 비활성화, 태양 그림자 비활성화도 유지한다.

로컬 Godot 4.7.2 / Linux에서 측정한 참고값이다. Android 실기기 결과가 아니며 OS 파일 캐시와 그래픽 드라이버 캐시를 비우지 않았다.

| 항목 | 기존 가져오기 정책 | GPU 압축 정책 적용 |
| --- | ---: | ---: |
| 실제 참조하는 텍스처 파일 55개 합계 | 104.72 MB | 94.72 MB |
| 실제 참조하는 가져온 자원 합계 | 147.04 MB | 137.04 MB |
| headless 자원 준비 시간 | 약 2.2–2.5초 | 약 0.26–0.30초 |
| 월드 생성 | 약 0.10–0.18초 | 약 0.10–0.12초 |

이 용량은 APK 전체 용량이나 GPU 메모리 사용량이 아니다. 캐시 디렉터리에는 이전 형식의 미사용 파일도 남으므로 디렉터리 전체 용량으로 비교하지 않았다. 소프트웨어 OpenGL 렌더링에서는 최초 화면 준비에 수 초가 추가로 필요했다. 서로 다른 화면 크기와 셰이더 캐시 상태의 실행이므로 전체 로딩 개선율로 환산하지 않는다.

`PROTOTYPE_LOADING` 로그에는 로딩 화면 표시, 자원 준비, 월드 생성, 준비 완료 시간을 기록한다. `PROTOTYPE_FRAME_READY`에는 실제 첫 게임 프레임까지의 시간과 텍스처 메모리를 기록한다. 화면 캡처 검사에는 `00-loading.png`도 남긴다.

## 추가 최적화 순서

1. **실기기 측정:** 보급형·중급 Android에서 최초 설치 후 실행과 재실행을 각각 측정한다. 로딩 화면 표시 시간, 첫 조작 가능한 프레임, 최대 프레임 지연, 텍스처 메모리를 위 로그로 비교한다. 가로·세로, 화면 키보드, 노치, 두 손가락 조작도 함께 확인한다.
2. **시작 프레임 비용 분리:** 자원 읽기가 빨라진 뒤에도 첫 프레임이 오래 걸린다면 외부 도시·조명·장비 생성 비용과 셰이더 준비를 따로 측정한다. 장비/물리 설정은 작은 묶음으로 나누고, 로딩 화면을 유지한 채 프레임을 양보한다. 충돌이 완성되기 전 이동을 허용하지 않는다.
3. **자산 최적화:** 큰 거칠기·노멀 텍스처의 모바일 해상도를 단계적으로 낮춰 글자·단말 화면과 구별해 평가한다. 모델의 기존 LOD를 활용하고 먼 외부 도시의 가시 거리를 줄인다. 보호된 장비 배치·문·충돌 지오메트리는 보존한다.
4. **배포 용량:** 이전 APK는 약 204 MB, 두 ABI의 Godot 라이브러리는 약 156 MB였다. ARM64 실배포와 x86_64 검증용 빌드 또는 스토어 AAB 분할을 검토한다. 패키지 ID·서명·저장 호환성을 유지하고, 배포할 바이너리 자체의 설치·덮어 설치 검증 방법을 먼저 확보한다. 이번에는 ABI나 서명을 바꾸지 않았다.
5. **모바일 분리 판단:** 현재는 콘텐츠·엔진·저장을 공유하고 화면·입력·렌더링 프로필만 모바일에 맞춘다. 실기기에서 위 최적화 후에도 목표 성능을 못 맞출 때 모바일용 장면/자산 프리셋을 분리한다. 조사 규칙과 저장은 공통으로 유지한다.

## 검증과 배포 조건

- 프로토타입 시나리오·저장 검사 462개, 서비스 검사 23개와 상세 사무실 smoke 검사.
- 기존 Native 규칙 452개, 업데이트 90개, 진단 166개 및 실제 사무실 `--qa` 검사.
- 1280×720, 1024×768, 960×540, 540×960에서 실제 열린 패널·터치 버튼의 화면 경계 검사. 인접 대상 선택·가장자리 조준·3.15m 거리·벽 차단·터치 선택·E 제거·대화 종료 카메라 유지도 검사한다.
- Linux 소프트웨어 OpenGL로 데스크톱/모바일 모드의 실제 렌더링 화면을 확인한다. 모바일 모드는 Android 기기 검증을 대신하지 않는다.
- 보호된 기능 인터페이스 101개, 지오메트리 해시 98개, 의자·키보드 배치 26쌍을 보존한다. 빌드 스테이징 및 CI 정책 검사도 실행한다.
- **새 EXE/APK 릴리즈 전에는 이번 소스로 Windows 실제 EXE와 Android 설치·입력·저장·덮어 설치·재실행 CI를 통과해야 한다.** 이전 0.3.0 릴리즈의 CI를 이번 UI·입력 변경 검증으로 대체하지 않는다. 안정화 후 main 병합한다.
